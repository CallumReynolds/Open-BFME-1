# PlayerTemplate destructor at 0x000E27A0

The complete body is 702 bytes. Its sole return is at +0x2BD, and the following bytes are INT3 padding. Every conditional branch remains inside the body. The non-deleting destructor receives its object in ECX, has no stack arguments and returns with a plain RET. Its return value is unused.

The matched vector destructor at 0x000E3D80 calls the ILT entry at 0x000181CE for each PlayerTemplate, advancing by 0x124 bytes. That five-byte entry jumps directly to 0x000E27A0. The scalar deleting destructor and matched STL destroy helpers use the same entry. The ILT oracle confirms `??1PlayerTemplate@@QAE@XZ` for the body. The existing ledger puts that real name on the ILT entry, and moving it to the body needs a documented name correction, so the body is recovered as the destructor of the translation-unit view `PlayerTemplate000E27A0` (`??1PlayerTemplate000E27A0@@QAE@XZ`) and the ILT row keeps its name.

The bank's single-layer string model omits AsciiString's inherited StringBase destructor. Reproducing the inherited empty derived destructor makes the complete target match. Adopting the canonical AsciiString header preserves that match. Merely adding an empty validate call to the original model preserves its register mismatch. ## Difference and type evidence

## ABI and unwind verification

The complete scalar deleting destructor at 0x000E2D70 passes its unchanged ECX receiver through 0x000181CE, then separately tests its own deletion flag and returns its pointer. The complete vector destructor and the three destroy loops at 0x000E3CC0, 0x000E3D20 and 0x000E3D50 also pass ECX without target stack arguments, advance by 0x124, and ignore the target's result. None supplies hidden return storage. Their raw bodies and checked inventories are retained under build/e27a0-retry/.

The three handle releases use the signed result of InterlockedDecrement on the dword at object +4. On a non-positive result they call virtual slot zero with the original receiver and a single four-byte deletion flag of one. The local owner stays address-derived. The complete standalone cleanup at 0x000877B0 has the same receiver, null guards, refcount operation and virtual call. The imported operation has one four-byte pointer argument and returns a signed 32-bit count. No concrete dynamic sound owner is asserted.

The retail and emitted unwind maps both contain 31 states, each with the same predecessor. Each cleanup action has the same member adjustment and instruction bytes after corresponding relocations are masked. Raw comparison and assertions are in build/e27a0-retry/eh-comparison-final.log, with the script in build/e27a0-retry/check_eh.py.

The array cleanup pushes the AsciiString destructor, count ten, element size four and the array at +0x38 into the CRT iterator at 0x009F6D76.
