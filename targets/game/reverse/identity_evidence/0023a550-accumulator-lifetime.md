# RVA 0x0023A550: accumulator lifetime and complete caller

The reconstruction is exact for the complete 383-byte retail body under `?rva0023a550@Rva0023A550HordeContain@@QAE_NPAUCoord3D@@@Z`. The tested base is `8fd286029cee70cd91c8d0c2a860ce73d9f07df2`; the model is `gpt-6.1-sol`. The source retains the bank's address-derived method and owner names. There is no independent evidence for an original semantic method name.

## Experiment and refutation

The saved bank reproduces 379 emitted bytes, 89 differing overlapping non-relocation bytes, four missing bytes and one shifted relocation operand. The decoded residue is an accumulator home reused from the dead output argument, together with its frame-size and epilogue consequences. Retail reserves two frame words, keeps the count at `[esp+0x10]`, and saves the receiver at `[esp+0x14]`. The bank reserves one word, uses the incoming argument at `[esp+0x18]` for count, and saves the receiver at `[esp+0x10]`.

The new hypotheses were that native lookup visibility or an earlier accumulator initialization would preserve the second local home. An unchanged one-word frame would refute each experiment. Exposing the complete native `GameLogic::findObjectByID` implementation, with or without the outer zero-ID guard, leaves the shorter frame. Declaring count early but initializing it after list begin also leaves the shorter frame. Initializing `float count = 0.0f;` before the output stores instead reproduces the complete retail instruction stream, including loop padding, both frame removals and all stack displacements. No compiler option or helper declaration changed in the retained source.

The original bank, every trial source, unedited probe outputs and the running results are retained under `build/worker-0023a550-run2/`. The baseline is `probe-00-bank.txt`; the successful trial is `03-count-before-zero.cpp` with `03-count-before-zero.log`. Trials 01, 02, 04 and 06 refute lookup visibility and declaration-only variants. Trial 05 changes the decorated parameter type, so its original-symbol lookup failure is not a byte measurement. The probe at the final source path is `probe-final-path.txt`. `add-match.txt` records the successful strict byte, string, constant, DIR32 and body checks.

## Boundary and caller ABI

The complete target ends after the second `ret 4`; its returns are at `+0x152` and `+0x17c`. All outgoing conditional branches remain within the extent and land on decoded instructions. There are no tail jumps, exception-registration states, owning-container changes or cleanup paths in this target. It accepts its receiver in ECX and one four-byte coordinate pointer on the stack, writes three single-precision values, and returns a boolean in AL.

The complete caller at `0x0041FCE0` has a shared `ret 4` at `+0xd1`. It reads its object pointer at receiver `+0xfc`, then the object's contain interface at `+0x1fc`. At `+0x41` and `+0x50` it invokes contain slot `+0x68`. At `+0x55` it pushes its output coordinate pointer, uses the returned interface directly as ECX without another adjustment, invokes interface slot `+0x200` at `+0x58`, and tests AL at `+0x5e`. On failure it copies all three dwords from the position accessor into that same output, and later uses the third output component in floating-point arithmetic. This proves the pointer width, argument order, receiver, output representation and boolean return independently of the target's byte equality. There is no hidden result buffer or caller stack adjustment after this virtual call.

The HordeContain constructor at `0x0023EAF0` stores vtable `0x010AF048` at complete-object `+0x20` and vtable `0x010AED58` at `+0xe4`. The former table's slot `+0x68` routes through ILT `0x00027831` to the complete 17-byte getter at `0x00230730`. Its non-null path returns receiver `+0xc4`, converting complete-object `+0x20` to `+0xe4`; its alternate path returns null. The latter table's slot `+0x200` routes through ILT `0x00021959` to the assigned target. This connects the complete caller to the installed target without inferring identity from a slot number alone. The constructor is evidence for these vptr stores, not a new claim about its unwind ownership.

The caller and interface getter are decoded in `retail-caller.txt` and `retail-interface.txt`; the tables are in `vtable-contain.txt` and `vtable-horde.txt`. The raw-byte call screen is only a lead; the relevant hit was validated on an instruction boundary within the complete caller. `extent-audit.txt` records all return offsets and confirms that each inspected conditional branch is internal and instruction-aligned.
