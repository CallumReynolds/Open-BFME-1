## Rejected hypotheses and reopening condition

The trial sources and logs reject native bool normalization; full native string forwarding; directory getter, prefix, and metadata special-member visibility; complete cache members and MapPlayers wrapping; native player construction and equality; iterator access and increment forms; entry and payload aliases; initial guard materialization; copy versus direct initialization; scoped output-result combinations; key and directory declaration lifetimes; initial-directory evaluation expressions; inlined output operations; argument-copy rotation; local output alignment; for-variable scope and function-packaging flags; donor one-argument path concatenation; generated frame-array storage; and position-local scope. Where an older lever was reopened, its new context was the measured named-result frame. Local alignment regresses and is not evidence of native alignment requirements. The earlier full-header controls omitted the visible concat(char) forwarder; corrected controls reproduce the original or named-result residue. Early in-class header trials are replayed with batch2.py, and their exact header snapshots are retained in build/writecache-004550c0/batch2-headers/.

The scoped byte gate fails. It also reports the missing binding for the exact std::equal<AsciiString> instantiation at the already decoded helper; no pin was added because the writer still differs. The helper's native implementation and ABI are retained, so a future exact conversion can add a justified binding through the normal procedure. No shared header, tooling, baseline, ledger row, or existing pin was changed.

Reopening needs a source-level explanation that recovers the original receiver and temporary homes while delaying the key spill, or new evidence about a hidden temporary or callable layer. Repeating the unchanged declaration-order or register spellings does not justify another retry. A newly decoded payload field or an oracle contradiction would refute the type conclusion and must be resolved before acceptance. There is no proof that assembly is required.
