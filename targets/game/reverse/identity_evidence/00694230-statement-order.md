## Retry hypothesis and located differences

The initial hypothesis was that file-read control flow or a temporary lifetime changed the bank's first allocation. It would be refuted for each tested form by an unchanged instruction stream. Every earlier verdict and the saved source were read before new experiments. The bank's differences are associated with their containing instructions in `build/audio-00694230-r8/trial00-residue.log`. Before `+0x80`, the record's EBX allocation instead of EBP changes register-saving order, makes its offset-zero load one byte shorter, shifts four relocation operands, and changes alignment padding. The remaining fifteen offsets are `+0x099`, `+0x0B3`, `+0x0B9`, `+0x106`, `+0x145`, `+0x14D`, `+0x177`, `+0x1A4`, `+0x1B5`, `+0x1BD`, `+0x1CA`, `+0x1F8`, `+0x1FE`, `+0x247`, and `+0x270`. Each exchanges EBX and EBP for the record or the zero/wait/buffer/size values. No arithmetic, data offset, or call target was guessed to remove them.

Changing file-read polarity, failure initialization, record/name aliases, packet lifetime, direct field views, register qualifiers, visible reporting and string helpers, and the explicit imported wait pointer did not improve the bank's allocation. Grouping read outputs, initializing the buffer, using an inline WAV decoder, deleting before assigning metadata, and several CPU or size settings worsened it. Reversing the two guard-default stores reduced the raw count to 100 while worsening instruction order; it was not used for the recovery. Trial40 instead reverses the independent compression/size assignments in both supported-format branches and is exact. The running measurements and named hypotheses are in `build/verdict.txt` and `build/audio-00694230-r8/measurements.jsonl`.

## Exception cleanup and destructor identity

The target has one unwind state, zero to minus one. The action at `0x00C472B0` adjusts ECX to `[ebp-0x38]` and jumps through ILT `0x0001E961` to `0x006915E0`. The complete 25-byte callee checks the ownership byte at object `+0x04`, conditionally releases the handle at `+0x00`, clears the ownership byte, and returns. There is no string or buffer destruction in the target's unwind map. The emitted candidate has the same state predecessor and receiver adjustment.

The existing `?release@Rva006915E0@@QAEXXZ` row at `0x006915E0` is opaque bookkeeping. Its own source describes this address as a scoped-mutex destructor. The independently read Zero Hour ScopedMutex class supplies the scoped-lock role and destructor, while BFME's decoded helper establishes the additional ownership byte. The ILT oracle confirms `??1ScopedMutex@@QAE@XZ` at this body (also checked using the actual ILT address) and contradicts `?release@ScopedMutex@@QAEXXZ`. The oracle alone is consistency evidence, not identity proof; the unwind role, complete ownership behavior, and donor class provide the independent evidence. The final source uses ScopedMutex with the existing `Rva006915E0` alias, and its emitted destructor independently reproduces the 25-byte helper. A destructor cannot be declared under the existing ordinary release-method decoration in C++, so the actual destructor binding needs one independently supported pin rather than a fabricated alias. The old opaque helper row is not renamed in this assignment.

The timeout path repeats without ownership. The missing-file and unsupported-format paths release before reporting. The ADPCM path deletes the original array, replaces its buffer with the decompressor output, and recomputes WAV information. The successful setter receives the final buffer, packet, size, and low compression byte before accounting and guard destruction. The stop path leaves the buffer alone, as retail does. Target metadata is in `build/audio-00694230-r8/eh-00694230.log`; object actions, direct helper comparison, imports, and oracle results are retained beside it.

## Refutation and collection limits

This recovery would be refuted by a final-path strict byte or relocation failure, a changed complete extent, a decoded value field absent from the declarations, a different unwind state/action or receiver adjustment, a contradicted destructor route, or a caller whose argument setup disagrees with the retained one-address thiscall ABI. The unknown complete EA decoration is not claimed. No assembly, shared-header edit, baseline expansion, synchronization, or Git metadata write is part of this assignment.

The working-tree `add_match` transaction passes the scoped gate, repoints the target, writes its tombstone, and removes the bank. Final-path probing again reports zero differences. The four STL dependencies and 25-byte destructor pass strict comparison; `build/audio-00694230-r8/unwind-action-strict.log` also verifies the complete eight-byte unwind action against the actual destructor's ILT route. The final scoped build passes source claims, bytes, all four diagnostic literals, recorded DIR32 identities, constants, and the body guard in `build/audio-00694230-r8/scoped-gate-python.log`. Pin consistency, the class gate, declared-definition coverage, direct source name regression, the field-name oracle, and the working-tree ILT and EA guards pass. The symbols append preserves the existing CRLF bytes exactly. The complete array-delete helper also agrees with the canonical cdecl pointer argument and both null/non-null return paths.

`build/audio-00694230-r8/check-csv-final.log` retains the required CSV check's failure: its Git-tracked attempt enumeration still includes the deleted bank, and reading that unstaged deletion raises FileNotFoundError.
