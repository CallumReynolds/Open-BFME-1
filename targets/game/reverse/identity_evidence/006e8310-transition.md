## Fields and arithmetic

The target reads mode at state +0, startFrame at +4, float duration at +8, and float RGB at +0xC, +0x10 and +0x14. It returns when duration compares equal to zero. At +0x49 it spills the fraction, then FCOMP against 1.0 and `test ah,0x41` make the reset condition strictly greater than 1.0. Equality and unordered comparisons continue. The saved bank's greater-or-equal guard was incorrect.

Before the optional mode-one swap, stack +4 holds the elapsed fraction and stack +8 holds one minus that fraction. In the loop, after the additional saved registers, stack +0x10 multiplies the stored lighting and stack +0x14 multiplies the receiver RGB. The saved bank reversed these default weights. The native swap loads the inverse weight through x87 and moves the fraction through an integer register. A temporary initialized from `to`, followed by `to = from; from = swap`, reproduces it.

GlobalData timeOfDay is read at +0x218. Its selected row advances by 0x6C, with three 0x24-byte lighting records. The three arrays begin at +0x224, +0x4AC and +0x734. Retail calculates blue, red and green in that order for each aggregate. Every component source and destination is accounted for by decoded instructions, rather than an allocation size or a template name. ## Experiments and falsification

The saved bank was reproduced as 555 bytes with 141 nonrelocation differences in build/transition-006e8310/trial00.log. Raw source snapshots and unedited probe output for each experiment are retained under build/transition-006e8310/. The running measurements and hypotheses are in build/verdict.txt. The strict guard and explicit blue-first assignments alone did not solve the fraction lifetime. Correct default weights reduced the difference to 47 bytes. Giving the fraction its own mutable weight local, using a literal frame scale, and reversing the swap temporary reduced the result to four bytes and then zero. The final bound source repeatedly probes as 555 bytes with zero nonrelocation differences. The native constructor experiment did not change code generation and was rejected. Literal changes alone did not solve the mismatch.

Any outgoing target branch, extra stack cleanup, different vtable target, differing component offset, or nonzero strict byte-gate result would refute the corresponding recovery claim. The ILT oracle contradicts the invented update and relay spellings; both retain their actual body address tokens and are treated as placeholders. Raw oracle output is in build/transition-006e8310/oracle.log. The EA evidence row supplies only the W3DDisplay.cpp file, not a method name. The Zero Hour W3DDisplay.cpp contains no equivalent transition body, so no donor body or donor comments were ported.
