# W3DDisplay draw: save-width context experiments

The target remains a partial reconstruction at revision d723fb900ff6674c0f0edc7e34de65f1d0a94cff. No authored draw body is byte exact. The preferred bank at targets/game/reverse/attempts/0x006f3fc0.cpp is unchanged because no trial improves its measured result. No function ledger, symbol pin, data record, shared header, policy or baseline is changed. ## Reproduced measurement

The bank emits 1184 bytes for the independently decoded 1184-byte retail extent. Its only probe-masked differences are +0x3E2 (retail 90, candidate 80), +0x3E9 (D7, C7) and +0x3EB (52, 50). There are no missing or excess bytes and no unaligned object relocations. This is a failed recovery, not evidence that assembly is necessary.

Fresh full decodes and checked_callees outputs are retained in build/draw-006f3fc0-writer8/; audit.log identifies the audited extents and every return or outgoing branch.

Capture consumes image and row stride as two dword stack arguments and returns with ret 8. Its complete loop advances across four-byte source pixels and copies three channels to the destination, advancing destination rows by the supplied stride. Save consumes image, unsigned width and unsigned height as three stack words and returns with ret 12. Its logical shift and unsigned loop guards support those dimension declarations. Render consumes ECX and one time word, returns AL on every exit and uses ret 4. The three debug helpers consume ECX and no stack words. The first-view getter and final screenshot slot consume only ECX with zero adjustment and no stack arguments. Unknown helper identities retain their existing address tokens.

The virtual-call audit is retained in build/draw-006f3fc0-writer8/virtual-audit.log with complete helper decodes and checked_callees logs.
