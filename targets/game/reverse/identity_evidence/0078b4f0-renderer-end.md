# Renderer state handoff at RVA 0x0078B4F0

The tested base revision is `c82e152d9961cf4b1b6ea98aad76377462bf0201`. The complete target is 1694 bytes, from RVA `0x0078B4F0` through the RET at `0x0078BB8D`; INT3 padding begins at `0x0078BB8E`. The reconstruction is `BfmeHub982::bfmeEnd982C0078B4F0` in `game/GameEngineDevice/Source/W3DDevice/GameClient/GUI/W3DAptRendererEnd0078B4F0.cpp`. Its address-qualified method and empty-row type retain the bank's descriptive words without asserting their original identities.

## Retry hypothesis and measured changes

The saved bank was recompiled with an explicit 1694-byte retail extent. It emitted 1697 bytes with 476 differing non-relocation bytes. The initial hypothesis was that its disconnected row array misrepresented a matrix temporary's construction lifetime. A temporary owning the row array changed the frame/copy sequence and worsened the result, so that hypothesis was rejected. Complete retail decoding then exposed a control-flow error: the JNE at target offset `+0x37E` reaches `+0x42E`, where projection setup begins. Only the cached view reset is conditional. The saved bank incorrectly placed projection setup inside that condition.

## Complete boundary and receiver contract

`build/78b4f0-run/retail-decoded.txt` retains the complete target, padding, caller at RVA `0x00786060` (301 bytes), ILT routes, vector iterator, empty callback and all four direct callees. `checked-target.log` reports no outgoing jump or conditional branch. All target paths join before one epilogue, which restores the `0x98` frame and saved registers and returns without stack cleanup. The target reads no incoming stack argument and saves ECX as its renderer receiver. The matched caller loads the same renderer global into ECX at `0x00786176`, calls ILT `0x00008D4B` at `0x00786182`, and consumes no return value. That complete five-byte thunk jumps to the target. The target therefore has a nullary thiscall contract with no observed return result, rather than the dump's nominal free-function signature.

The landed renderer constructor at RVA `0x0078B310` independently establishes three 64-byte matrix fields at `+0x10`, `+0x50` and `+0x90`, a DX8VertexBufferClass pointer at `+0xD0`, and the leading byte flags. The target saves the prior view and projection to the latter two matrices, transposes all sixteen cells of the world matrix, and updates the leading byte flags at `+0x00` and `+0x01`. The inherited texture, mode, stencil and trailing counter labels are retained from the bank; this function does not independently name them. The new source includes the existing native math and DX8Wrapper declarations. `preflight.log` records equal compiler switches for the bank, neighbouring constructor and final source; no compiler-switch experiment is needed to explain this recovery.

## Helpers, values and ownership

The complete 48-byte iterator at RVA `0x0005C600` receives destination, stride, count and callback on the stack, calls the callback with each destination in ECX, advances by the stride, and returns with RET16 on both its empty and nonempty paths. Target offset `+0x51E` passes callback VA `0x00445561`; `+0x541` passes count four and `+0x558` passes stride sixteen. ILT RVA `0x00045561` jumps to the complete three-byte callback at RVA `0x000FBB40`, which executes only `mov eax, ecx; ret`. It reads and writes no object field. This proves an empty nullary thiscall callback and the storage stride, but does not prove a Vector4, scalar, pair, or SpawnBoneRow identity. The source retains the bank's separate empty row array through the address-qualified alias `SpawnBoneRow000FBB40`. Its four float labels are unused storage, not a type inference from allocation size. Its declaration uses the inherited `SpawnBoneRow` constructor decoration because that is already pinned and recorded for this callback. Existing `Rva000FBB40::get` is another opaque view of the same three bytes, rather than proof of the callback's source type.

Matrix values are established separately by every field access: the unchanged native Vector4 constructor and assignment read/write X, Y, Z and W, and Matrix4::Transpose constructs four column values and assigns all sixteen output cells. The target's world transpose at `+0x4DD` through `+0x624` consumes the same sixteen renderer fields. No STL key or payload inference is involved. The target and vector iterator have no exception registration, unwind state, exceptional cleanup helper or owning row destructor. The callback has no throwing operation or owned member. Constructor unwind matching is therefore inapplicable to this body.

The direct cdecl viewport callee (26 bytes) consumes one pointer and forwards the device and pointer to virtual slot `+0xBC`. Get_Preset (22 bytes) consumes one preset index, increments the returned material's count at `+0x04`, and returns its pointer in EAX. The target then adds the render-state reference, releases the previous material through RefCountClass::Delete_This at slot zero only when its decremented count reaches zero, stores the new material, and releases its local owning reference. Those are the two virtual calls at `+0x654` and `+0x67B`, both nullary thiscall calls without receiver adjustment or hidden result storage. The indirect device transform calls at `+0x1BA` and `+0x4D1` pass device, transform index three and a 64-byte matrix pointer on the stack. The four-byte resolution objects use existing signed declarations and unsigned casts, while the target's viewport stores copy their bits without arithmetic. No global image address appears as a source literal.

## Names and refutation conditions

The matched caller establishes the target route and receiver but inherited its invented `bfmeEnd982C` label. Direct oracle checks of the body and callback contradict both inherited decorations. The target replacement preserves the descriptive words and adds its own address token; the callback retains its existing recorded decoration and gains an address-qualified source alias. Raw oracle output is in `preflight.log`. The target's new decoration remains contradicted as a hash assertion, while the guard treats the address-qualified method as a placeholder. The unchanged callback decoration remains an inherited identity limitation, not evidence of the original type. EA evidence supplies only the W3DAptRenderer source file, with no method-name pairing. No original renderer class, callback class or method identity is claimed.

These ABI and layout conclusions would be refuted by an aligned complete caller supplying stack arguments or consuming a return, a callback field access, an outgoing target branch omitted from the extent, a constructor access contradicting the matrix offsets, a material receiver adjustment, or a strict gate resolving any relocation to a different retail object. A mismatch in any applicable check blocks collection even if the masked probe is exact.
