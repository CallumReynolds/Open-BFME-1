# Query and unlink donor experiment

The tested revision is 9f335a9ec9ff012c5103195540fa82ccc3e7877e. Open BFME 2 donor Code/Libraries/Source/Apt/AptDisplayList.cpp at game.dat 0x006F7D50 is a 39-byte wrapper that returns its unlinked item. Its separately compiled unlink helper supplies all four link operations. The new hypothesis was that a complete inline version of that helper and its result lifetime would remove the saved body's redundant argument store and field-address CSE. It does not produce an exact BFME 1 reconstruction.

The complete BFME 1 body ends with RET 4 at +0x44 followed by INT3 at +0x47. ECX reaches the matched BfmeQuery1279 member unchanged, with four pushed arguments. The fourth argument points at the wrapper's incoming argument home and the third points at its only local dword. After the call, EAX reloads the replaced incoming value. The target conditionally updates the neighboring links, then zeros fields +0x54 and +0x58. It leaves the found item in EAX on exit. No complete caller establishes whether that final value is a declared pointer return; the bank's existing void declaration is retained, and a pointer-return donor trial is not accepted as ABI evidence.

The complete actual provider at 0x008BD0F0 is 185 bytes with RET 16. Its key walk compares the first argument as a signed 32-bit key against node +8, and follows next at +0x58. Its name walk reads the handle at +0xC and the payload's length and text. All provider returns install both output pointers. This independently supports the key and output-home behavior; BFME 2's 16-bit node key and shifted link offsets do not apply. The existing void-pointer spelling is used only as the repository's recorded 32-bit ABI binding. The target's link layout remains address-qualified, and no semantic node identity or new pin is claimed.

The preferred bank reproduces 79 bytes with 52 differences and a misaligned call relocation. Direct query and inline unlink forms, with either a void or pointer return, emit 74 bytes. A signed-depth parameter has the same result. A visible copy of the actual noinline query provider independently probes exact at 185 bytes, but changes the wrapper to 66 or 70 bytes and does not repair it. Correctly disabling global optimization emits 111, 114 or 117 bytes. Earlier /Og- spellings before /O2 were overridden and are not negative compiler evidence. The bounded family search exhausts two trials without improvement.

The best admissible measured source is build/x15/8bd760/bank.cpp. It keeps the existing method and link-field names, uses the parameter's output home directly and clears the two pointer representations through intrinsic memset. On the proved x86 representation this clears exactly those eight bytes. It emits 68 bytes with 36 non-relocation differences, first at +0x20, and its call relocation aligns. Its initial query and reload sequence agrees through +0x1F. The remaining code hoists the link-field address, briefly saves ESI and chooses a shared zero register. This remains a partial. Captured plain or volatile link locals do not change the ordinary 74-byte result; wide and pair-view clears do not recover native code and are not used in the bank.

The strict scoped comparison fails in build/x15/8b-final-strict.log. Every trial remains under build/x15/8bd760/, and the previous bank is preserved by the immutable attempt archive.

Reopening requires supported access or lifetime evidence that removes the field-address CSE while preserving the native query output home. An exact source must also settle or explicitly bound the wrapper's unobserved return contract; the donor's pointer return alone cannot prove it.
