## Compiler experiment

The unchanged preferred bank emits 862 bytes against 873, with 318 non-relocation differences. Its first actual instruction change occurs at +0x1E5; earlier differences are branch destinations affected by the later length change. At the digit loop the bank caches `char current`, omits the EBP save, assigns the length to EDX and the next index to EDI, redirects an already-seen decimal point directly to the digit test, and omits the retail loop-entry jump and alignment. The later cleanup offsets and branch displacements consequently move. The original measurement is retained in build/8c4a30-run/baseline-probe.log.

The new hypothesis was that caching the character collapsed source-expression lifetimes and control-flow facts that the native repeated string accesses preserved. A nested decimal-point guard and an indexed accessor retaining the local each reproduce the old 862-byte result. Removing the cached `current` and reading `string.text()[index]` at each use reproduces all 873 bytes. It restores the EBP and EDI saves, the repeated-dot fallthrough, the loop-entry alignment and all later branch offsets. Each trial source and unedited output is retained under build/8c4a30-run/ with prefixes 01-dot-nested, 02-repeated-current, 03-at-accessor and 04-canonical-getter. The final source probe is build/8c4a30-run/source-probe.log. This result refutes the earlier claim that the remaining register choice could not be expressed by ordinary C++.

## Identity limits and refutation

The ILT oracle API reports UNTESTABLE for the address-qualified target, the existing converter, both CRT import thunks and the version getter in this baseline. No new authentic function or class identity is inferred from that result. The descriptive bank names are preserved. The retired dump name has an address-only compatibility pin because two existing C++ callers and one dump still reference it.

A decoded call consuming a full-width result, an argument cleanup inconsistent with one pointer, a branch escaping the target extent, a switch destination outside the converter's decoded code, or a cleanup releasing a different object would refute the corresponding ABI or ownership claim. A relocation-aware scoped gate mismatch would refute exact recovery even when the masked probe matches. The converter's data-inclusive linear decode failure is resolved by its explicitly decoded switch tables, not ignored as code.
