# Radar surface clear descriptor lifetime

This retry starts from revision `07a219def195b93798ffefa35aef97d473559f40`. The preferred reconstruction remains a partial. No production function, pin, shared header or function ledger row is changed.

## Result and remaining differences

The original bank emits 508 bytes with 142 differences outside object relocation fields. The revised bank emits 508 bytes with 89 such differences. Both measurements use the independently checked retail extent. The revised source retains the existing `W3DRadarResetSurface::clear(unsigned int)` name. Its complete probe is build/clear008fc830/final-bank-report-abi.log. The strict repository byte comparison fails in build/clear008fc830/scoped-gate-report-abi.log, so this is not an exact recovery.

The retry hypothesis was that the color residue depended on the descriptor update and local value lifetimes, rather than requiring a different spelling of the color mask. Updating `description.Height` before copying it into the row counter reproduces retail's raw AL input, DL fill mask, ECX format comparisons and ECX row count. A split-byte block value also reproduces the EDX low-dword and EBX high-dword loads. Neither change alone closes the body.

The remaining instruction differences occupy two regions. At `+0xF0`, the reconstruction writes the shifted height back to the descriptor. Its white-pattern initialization therefore moves four bytes, and its zero-row branch becomes a short branch at `+0x123` instead of retail's long branch at `+0x11F`. The instruction bytes agree again from `+0x125` through `+0x1AF`. At `+0x1B0`, the reconstruction restores EBP before the final error test, whereas retail restores it at `+0x1F2`. The final string, HResult and crash-report arguments also trade order with their ECX receiver copies. The resulting call-site displacement leaves four object relocation sites out of alignment. The exact differing bytes, offsets, object hashes and relocation entries are retained in build/clear008fc830/best-bytes.json.

The null branch joins the epilogue, every conditional destination stays inside the extent, and there is no outgoing tail jump or exception registration. Raw evidence is build/clear008fc830/retail.log and build/clear008fc830/callees-target.log.

All six direct caller hits were checked against instruction boundaries in complete decoded ledger bodies. Five calls push zero. No caller examined uses the return value. These observations support the one-pointer receiver, one stack word and low-byte input representation. They do not distinguish an original bool parameter from an unsigned-byte parameter. Existing matched `reset` and `clearShroud` sources name the preserved bank identity. ## Rejected hypotheses and reopening condition

Complete static helper visibility, in-class helper visibility, descriptor copies and aggregate result accessors do not remove the extra height write while retaining the successful register schedule. Making both descriptor consumers visible removes that write but returns to the 507-byte raw-byte result with the wrong AL/CL allocation. Separate descriptor update spellings and local references reproduce the same outcomes.

Native split-byte assignment fixes the low/high dword ordering only in the improved descriptor-update structure. Typed block cursors, value references, file-scope block types and the inspected VC7.1 fill algorithms do not close the remaining regions. Native nested branches preserve the desired white-block instructions without a descriptor write, but duplicate the memset loop and enlarge the function. Explicit common-fill labels return to the old register schedule. Switch predicates change the branch ordering. Row counter and cursor value objects, argument-slot reuse, byte extraction views and signed 32-bit declarations do not improve the bank.

Error-helper layers, the verified HResult wrapper, native virtual stream operators, reference results, explicit return paths, scope cleanup and compiler barriers do not delay the EBP restore. CPU scheduling controls do not improve the preferred reconstruction. These are measured negative results, not proof that C++ cannot reproduce the target. Raw trial sources and unedited probe output are retained under build/clear008fc830/. The running list of hypotheses and measurements is build/verdict.txt; structured receipts are build/clear008fc830/measurements.jsonl.

Reopening needs a distinct native lifetime or control-flow hypothesis that removes the descriptor write while retaining the already matching raw-byte mask, format checks and block loop, or that delays the final EBP restore without changing those instructions. Repeating the scalar mask, pattern register swaps or already tested helper spellings supplies no such evidence.

## Checks and limits

CSV validation, pin consistency and the explicit class-view check pass. Direct source-name comparison reports no regressions. This revision of the name_regression CLI accepts Git revisions rather than the file paths in the worker brief, so its file-path invocation fails; the direct comparison is retained separately. The unmatched-definition check refuses the unlanded scratch source because it has no function ledger row. Neither refusal is bypassed. The failed strict byte gate remains the blocker to conversion. No full gate is required for a bank and evidence-only change.
