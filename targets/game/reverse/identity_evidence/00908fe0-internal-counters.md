## Closing experiment

Visible in-class EndScene and Present dispatch changes the allocation context so all later registers match, but with external counter declarations the first table load moves past the counter-clearing store. Passing an explicitly captured table into the inline method restores the old register residue. Strong external definitions and selectany definitions do not repair that scheduling. Defining the two counters as internal TU storage, with their addresses unescaped, makes the in-class dispatch source match the entire parent without compiler-option changes. This supports an alias-information explanation: the compiler can separate the device vptr from the internal counter store. It does not establish the original source spelling or counter semantics.

The internal counter definitions correspond to VAs 0x013405C4 and 0x013405C8. Both retail initial dwords are independently verified as zero in .data. COFF records the candidate counters as internal symbols with distinct four-byte storage. Their inherited address names claim only storage identity, and DIR32 verification must bind every use consistently. No numeric image-address literal, new pin, shared declaration, assembly or baseline allowance is introduced. The donor's original comments in the corresponding End_Scene statements are retained.

The explanation would be refuted by a changed direct caller contract, a branch or return outside the checked extent, a different device slot or stack contract, a nonzero counter initializer, an inconsistent DIR32 binding, or a different unwind destructor/receiver adjustment. Replacing either the in-class dispatch context or the internal-counter alias fact is an independently measured negative control.
