# DX8Wrapper::End_Scene reconstruction

The tested revision is 5ef5ef7df5384303e915d0a24fa47d2f2f4314fa. This remains a partial reconstruction. The full parent is 616 bytes. Retail returns at +0x267, and INT3 padding begins at +0x268. Every conditional branch stays inside the parent, and there are no outgoing tail jumps. The complete caller at 0x008FD880 passes one stack slot, calls 0x00908FE0 at +0x1A, and removes that slot afterward. The target reads its low byte. That caller's matched WW3D::End_Render source, the existing End_Scene pin and the Zero Hour body support DX8Wrapper::End_Scene(bool).

The initial hypothesis was that the bank's numeric-address state accesses concealed alias information that named declarations would expose. The original bank reproduced at 607 bytes with 174 differing bytes, plus nine absent tail bytes. Named prefix storage moves the first load before FS registration, as retail does. Named state offsets restore the buffer-test scheduling. The canonical RenderStateStruct reproduces those accesses without a private replacement layout. Its shader, material and texture prefix and buffer suffix agree with the complete decoded accesses. The texture-stage limit remains a signed dword at caps+0x278; the canonical D3D8 caps accessor uses a different layout, so the source retains the bank's explicit D3D9 view.

An owning four-byte handle assignment preserves the second texture null guard that the raw-pointer expansion lost. The emitted destructor is the complete 12-byte null-test and tail jump to 0x009EB7A0. That complete 36-byte target decrements the low word at +4, tests the disposal flag in the same dword and conditionally tail-dispatches slot +0x20. The parent has one unwind state. Its eight-byte cleanup at 0x00C5B5C0 adjusts ECX to EBP+4 and jumps through ILT 0x00030652 to 0x0005CC00. The candidate emits the same adjustment, one-state unwind predecessor and zero try-block count. The bank's BfmeHandleCX spelling is contradicted by the oracle for all tested access and const decorations. The local view therefore keeps that word and appends 0005CC00; it claims the witnessed storage and cleanup ABI, without claiming the original class name.

Reading render_state.material directly, rather than caching it in a local, reproduces retail's register-based reference decrement and the complete epilogue. Applying the index mask at the final assignment restores its earlier load and later store. Separate Present device and vtable temporaries then reduce the remaining parent differences to +0x5F and +0x66: retail uses EDX for the table while the candidate uses ECX. The other instruction forms, stack offsets, branches and call-site positions agree. This is a measured compiler residue, not an exact recovery.

The call at parent+0xC0 reaches 0x009DB560. Its complete 12-byte body loads the incoming dword, pushes it, invokes KERNEL32!Sleep through IAT 0x01358F30 and returns with plain RET. It is a cdecl wrapper with one unsigned 32-bit argument. The matched nonport.c implementation independently supplies the same wrapper shape. Its ledger entry at this address is an alias whose object symbol is _msleep, but _msleep itself resolves only to the separate body at 0x00854370. The existing no-argument dump decoration cannot express the witnessed argument. The new address-derived Rva009DB560Sleep(unsigned long) binding therefore names this body specifically. Its identity would be refuted by a different decoded target, stack cleanup, argument width or imported operation. No semantic msleep identity is added to this address.

The indirect device calls have stdcall stack contracts at slots +0xA8, +0x44 and +0x0C. They consume respectively the receiver alone, the receiver plus four null arguments, and the receiver alone. Present and TestCooperativeLevel return a signed HRESULT in EAX. The debug chain separately witnesses an unadjusted ECX receiver, slots +0x60 and +0x6C, two zero stack arguments for the latter, and pointer results consumed by subsequent calls. Its owner remains the inherited opaque debug view. The four-byte engine-reference helpers independently decrement vertex+0x10 and index+0x08 and return without stack cleanup.
