## New hypothesis and observed result

The incoming bank hoisted the stride out of the normal-fill and UV-copy loops. Retail instead loads the stack stride at +0xB30 and +0xB72 and uses its stack home again in the UV generator. The retry hypothesis was that these reads and the order of the source, count and destination captures account for substantial apparent register allocation differences. It would be refuted if reproducing those reads and capture boundaries left the measured residue unchanged.

Keeping the source setup before the destination setup improved the incoming body. A volatile local then represented the observed stride reads, with an explicit per-iteration step in the normal-fill and UV-copy loops. This restored the full extent. The qualifier is a reconstruction of these observed accesses, not proof of the original source spelling. An explicit location-offset temporary and count declaration before the source capture improved the allocation further. The UV reset helper keeps the original Vector2 local and its established name. A compiler memory barrier after the final transform update improves the exit-store schedule without emitting an instruction.

The old unpinned C alias for the sorting call is removed. The retry uses the existing SortingRendererClass::Insert_Triangles decoration and a reference cast from the witnessed 12-byte center view. The complete callee reads Center.X, Center.Y and Center.Z, but does not read a radius. Constructing a full canonical SphereClass also compiled, but moved the center's frame slot and measured worse. This reference cast states the caller's decoded layout without changing a shared header or adding a pin.
