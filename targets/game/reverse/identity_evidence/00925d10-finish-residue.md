## Identity, extent, and ABI

The complete 53-byte MeshClass::Get_Deformed_Vertices wrapper at RVA 0x0092C350 loads its model receiver from this+0xC8 and calls 0x00925D10 at wrapper+0x2C. It pushes the tree result, the normal destination, and the vertex destination in that order. Its virtual call uses the container at this+0x84 and slot 0xE4, passes that container as ECX, and consumes the full EAX result as the tree pointer. The canonical declarations in mesh.cpp and meshgeometry.h name the operation MeshGeometryClass::get_deformed_vertices(Vector3*, Vector3*, const HTreeClass*). This target has no indirect calls, hidden return storage, or receiver adjustment. Its only direct call is the seven-byte counter at 0x009371E0, which increments one global dword and returns without consuming arguments.

The complete target decode has no external conditional branch or tail jump. The three initial null guards, the nonpositive vertex-count path, the zero-run paths, and both deformation branches all reach the shared return sequence. RET 12 begins at target+0x65F and ends at +0x662, where INT3 padding starts. The independently decoded extent is therefore 1,634 bytes. Raw records are build/skin-00925d10/retail-00925d10.txt, build/skin-00925d10/retail-0092c350.txt, build/skin-00925d10/retail-009371e0.txt, and their checked-*.log files.

The bank's BfmeDst1016::bfmeSet1016 name is an inherited reconstruction label, not independent identity evidence. ## Independent storage and ownership evidence

The complete vertex loader at 0x00927360 selects the shared buffers at owner+0x30 and +0x34. Its alternate path writes the newly constructed buffer to +0x34, obtains its array at buffer+0x0C, and copies all three four-byte coordinates from each 12-byte input record. The complete normal selector at 0x00927230 returns array storage from the buffer at +0x40 or +0x44. The complete normal loader at 0x009274C0 writes all three coordinates and advances by the read's 12-byte result. These field operations establish the vector payload; allocation size alone is not the evidence.

The complete influence loader at 0x00925380 reads all four unsigned-short fields of each eight-byte input record and writes them to four separate planes. For vertex i and vertex count N, those planes are links[i], links[N+i], links[2N+i], and links[3N+i]. Its grouping loops compare all four fields. Its final run writer stores the first bone index and the run length as two consecutive unsigned shorts. The target consumes the second word and advances the link pointer by that length. The accessors at 0x009246B0 and 0x00924760 keep the link and run ShareBuffer owners at +0x58 and +0x5C. Their complete decoded bodies and those of the loaders are retained as retail-*.txt and checked-*.log files in the task directory.

The complete HTreeClass::Get_Transform body at 0x00924860 reads the pivot-array pointer from tree+0x14, multiplies the index by 0xB4, and returns the address at pivot+0x44. ## Every remaining difference

The complete weighted setup, matrix copies, native row scaling, integer control flow, and pointer advancement match outside the intervals below. The single-bone vertex loop also matches. A symbolic trace of one decoded iteration of each loop checks every floating memory operand against the source coordinate or matrix coefficient it denotes. All corresponding rows consume the same multiset of products and translations. The ordered trees differ in the weighted loops and the single-bone normal loop. This comparison does not claim identical floating-point rounding. The tracer and its output are build/skin-00925d10/trace_arithmetic.py, build/skin-00925d10/arithmetic-summary.json, and build/skin-00925d10/arithmetic-A.txt through arithmetic-D.txt.

In each weighted Y and Z row, retail evaluates the second matrix's Z product before the first matrix's Z product, and the second matrix's Y product before the first matrix's Y product. The bank reverses those two product pairs. The Y pair uses one three-byte and one four-byte memory multiply, so swapping them also moves the intervening FADDP and following instruction boundaries. These are decoded arithmetic-order differences, not evidence for a different field offset. The single-bone normal rows additionally differ in multiplication operand orientation. The bytes at +0x5C7 and +0x5E1 encode the opposite base/index ordering for the same two store addresses.

## Rejected hypotheses and reopening condition

Native HTree getters, the decoded pointer signature, native base classes, const source arrays, typed run records, direct native array returns, and the neighbouring library's /MD and /EHsc flags preserve the residue. Explicit /G6 and /Ob1 also preserve it. /G7, /arch:SSE, and /Op produce worse bodies. The original ww3d2.dsp release configuration independently specifies /G6, /MD, /GX, /O2, and /Ob2.

A trial that includes meshgeometry.h, defines the real protected method, and accesses the BFME fields through the retained bank layout view also preserves exactly the original residue. It passes class_gate without a private copy of MeshGeometryClass or a header exception. The source and raw probe are build/skin-00925d10/t78-canonical-direct-arguments-1.cpp and build/skin-00925d10/t78-canonical-direct-arguments-1-probe.log. The check's raw output and return-code receipt are build/skin-00925d10/canonical-class-gate.log and build/skin-00925d10/canonical-class-gate-receipt.json. Therefore canonical declaration integration is not a prerequisite blocker for the remaining arithmetic work. Calling the native noncreating bone-link accessor instead emits an additional call absent from retail and makes the comparison worse.

Native dot products, Rotate_Vector, complete weighted array helpers, per-row helpers, native Vector3 result temporaries, native setters, paired weight vectors, scalar product temporaries, matrix arrays, matrix assignment/declaration alternatives, coefficient references, independent countdowns, pointer-lifetime partitions, and weight/copy statement-order alternatives all fail to improve the bank. Exposing the complete counter helper with noinline changes its caller's register preservation and makes the result worse. Named weight inputs and buffer handles reach the same worse compiler state. Removing all integer-pointer aliases under the proper pointer signature emits 405 differences; compensating actual weight lifetimes recovers the original 92 but does not improve it. No unused locals or dead conditional blocks were added.

The raw discriminator for a sample-first row helper changed the instruction result, so a bounded search checked all four-reference argument orders. None closes the residue. A second bounded search checked actual pointer/countdown/weight lifetime interactions. Their manifests are named by build/skin-00925d10/row-parameter-search-location.txt and build/skin-00925d10/interaction-search-location.txt. The current source has no applicable generated sib or register spelling; shape_family_levers reports that fact. These experiments do not prove that every possible C++ spelling is exhausted or that assembly is necessary.

Reopen with independent BFME weighted-transform source, a native inline operation whose complete implementation changes the remaining arithmetic trees, or a specific declaration/lifetime hypothesis that predicts these measured offsets. A repeated 109-byte screen, allocation-size inference, another ungrounded local-count sweep, or an untestable alias name does not supply that evidence. No reconstruction was installed in game/, and no ledger or pin was repointed.
