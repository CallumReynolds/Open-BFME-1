# Recovery at 0x009BFA40

The tested base is `95eeb3bef370a7cd730b0ad5f228c317c8756e72`. The donor is Open BFME 2 `Code/Libraries/Source/VP6/DeblockNonFilteredBandWmt.cpp`, `_DeblockNonFilteredBand_WMT` at game.dat RVA 0x001D0340. The new hypothesis was that its C++ outer loop, aligned locals and two SIMD kernels would reproduce the BFME 1 target after independently mapping its globals. Any non-relocation byte difference would refute direct portability. The initial port, the caller-compatible signed fragment argument and the final source each emit 4068 bytes with zero non-relocation differences. Raw measurements and exact trial sources are retained under `build/deblock-009bfa40/`, including `01-donor-probe.log`, `02-signed-first-probe.log` and `03-final-probe.log`.

The earlier scalar bank emits 2743 bytes with 2673 differing bytes in the overlapping extent and 1325 missing bytes. Its raw measurement is `build/deblock-009bfa40/00-original-probe.log`. The donor supplies both previously missing SIMD kernels and the original local declaration order. It also shows that the first-fragment condition skips the vertical kernel, rather than testing whether q exceeds 3. Both assembly blocks contain MMX and SSE2 operations; there are no standalone scalar assembly blocks to port. The scalar setup, broadcasts, boundary samples, accumulator reductions and loop control remain C++. The measured scalar bank and the landed MMX siblings establish the code-generation blocker for retaining these SIMD kernels.

## Boundary and callback ABI

The complete target decode contains 960 instructions over exactly 4068 bytes. It begins with an aligned stack frame of 0x144 bytes. Its only return is at +0xFE3 after restoring EDI, ESI, EBX, ESP and EBP. Twelve INT3 padding bytes follow before the independently landed 0x009C0A30 entry. The empty-range branch at +0x58 reaches the epilogue at +0xFDD. The branch at +0x707 reaches the vertical kernel at +0x739, the first-fragment jump at +0x734 reaches the latch at +0xFD3, and the back edge at +0xFD7 reaches +0x80. Every branch destination lies on a decoded instruction inside the extent. There are no direct calls, indirect calls, tail calls, exception handlers, containers or cleanup helpers. Raw evidence is `build/deblock-009bfa40/target-complete.asm`, `checked-callees.log` and `evidence.log`.

The complete 881-byte installer at 0x009B0D60 stores VA 0x00DBFA40 into callback slot VA 0x01356E94 at +0x70 in its SSE tier. Its MMX and scalar tiers install different bodies in that same slot. The complete 488-byte `copyPlane009AEEE0` caller loads this slot at +0x18 when context mode is at least 2. Its indirect call at +0x15E pushes seven dwords in reverse order: table pointer, fragment index, block count, stride, destination, source and context. The caller removes 28 argument bytes at +0x170 and does not consume a return value. The target accesses exactly these seven stack slots, with no receiver adjustment or hidden return storage, and ends in plain RET. The declaration therefore uses cdecl, a void result, byte pointers, unsigned stride and count, a signed fragment-index argument consistent with the canonical caller, and a pointer to const unsigned table entries. Raw evidence is `caller-complete.asm`, `installer-complete.asm` and `checked-caller.log` in the trial directory. A different installer assignment or different argument setup in the decoded caller would refute this ABI association.

## Context and data identity

The target reads an integer table selector at context +0x0C, a pointer to four-byte per-fragment table indices at +0x24, and a pointer to four-byte activity accumulators at +0x28. The horizontal pass looks up index plus count and updates accumulators index and index plus count. The vertical pass looks up index and updates accumulators index minus one and index. All accumulation elements are loaded and stored as dwords; sample buffers and reductions use unsigned words. The bank's `Rva009BFA40Ctx`, `m_tableIndex`, `m_fragmentQIndex` and `m_fragmentVariances` names are retained. The canonical caller's local `Rva009AF200Context` declaration has padding over +0x24 and opaque scratch storage at +0x28; this target-specific view refines those accesses without changing a shared header. No canonical shared header is registered for this view.

The shared table pointer retains the recorded `g_rva01356A9C` identity. Its lookup is unconditional before the range guard. The seven remaining relocations read complete 16-byte constants: eight unsigned words of 3 at VA 0x012D87C0, of 4 at VA 0x012D87D0, and of 1 at VA 0x012D8820. Each byte sequence was read directly from BFME 1 retail and compared with its source initializer. The data-row writer proved all three extents and wrote their rows, but failed afterward when stamping its receipt inside the read-only Git directory. Raw outputs are `data-threes.log`, `data-fours.log` and `data-ones.log`. The coordinator must regenerate those writer receipts before committing; the scoped data verification checks the actual rows independently.

The old bank's descriptive function stem is retained in `_DeblockLoopFilteredBand_WMT_Rva009BFA40`; the address suffix makes the identity explicitly local to this body. The donor's different descriptive name is not adopted as a proven BFME 1 identity. BFME 1 has no matching pin or EA evidence row proving either original VP6 function spelling. The oracle Python API reports UNTESTABLE for both spellings and the address-bearing name. The address identity and callback ABI, rather than a guessed vendor name, are the recovery claim. A compatibility pin for `?d_009bfa40@@YAXXZ` preserves the matched dispatch installer's existing address-only reference to this body.
