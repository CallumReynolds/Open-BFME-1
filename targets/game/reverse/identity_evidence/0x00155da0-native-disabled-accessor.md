# AIGroup private object attack at 0x00155DA0

The working-tree conversion recovers the complete 576-byte body. The strict source-scoped gate passes, including call relocations, the recorded global address and the function boundary. The constructor-failure cleanup also matches its separate retail body. The tested base revision is 5ef5ef7df5384303e915d0a24fa47d2f2f4314fa. The model is gpt-6.1-sol.

## Experiment and refutation

The saved bank emits 573 bytes. Its probe reports 189 overlapping non-relocation differences; counting its three missing target bytes gives 192 differences. Correcting the command receiver from the bank's +0x24 to +0x20 does not by itself change this count. The original bank and this corrected control are preserved as build/attack155da0/original.cpp and build/attack155da0/layout-base.cpp, with raw probes in build/attack155da0/original.log and build/attack155da0/layout-base.log.

The new hypothesis was that the bank's raw disabled-mask expression hid the native STLport bit-access structure and changed subsequent compiler choices. The Zero Hour Object declaration implements isDisabledByType through BitFlags::test, which delegates to STLport bitset::test. An unchanged instruction and relocation result after restoring that structure would refute this hypothesis.

The native bitset access produces a 576-byte exact masked result. The final source includes canonical Object, Thing, Coord3D and command-source declarations. Its isDisabledByType accessor applies STLport bit access to the canonical mask word. The bitset view spans sizeof(m_disabledMask) * 8 bits; it does not claim to identify the original template's logical capacity. Only DISABLED_HELD, index 3, is used. Retail reads the low byte at Object+0x1A4 and tests bit 3.

The control's instruction differences are at the iterator first-call vtable temporary (+0xD2 and +0xD6), the contain-call temporaries (+0xFF, +0x103, +0x111 and +0x115), the AL/CL calculation at +0x12B through +0x136, and the order and register of the attack-type reload at +0x140. The control hoists one command-receiver LEA to +0x16B where retail emits separate LEAs at +0x174 and +0x184. That missing LEA shifts subsequent instructions by three bytes, including nine relocation sites and the epilogue. The early forward-branch displacement differences are consequences of that shift. The native bit accessor removes this entire residue. These measurements establish source sensitivity; they do not identify a particular internal compiler algorithm.

## Direct calls, ownership and exception cleanup

Both ordinary attack and force attack reach their existing 214-byte AICommandInterface bodies at 0x001535A0 and 0x001537B0. Every return consumes three stack arguments. Their receiver is the command view at AI+0x20, as the target instructions and the separately matched groupIdle source show. The garrison else branch calls ordinary attack. The bird branch instead reaches 0x001536B0, command 0x39, whose complete body consumes only victim and source and returns with ret 8. The final source calls the existing aiBfmeCommand39 declaration through an inline, absent-from-retail helper retaining the bank's aiBfmeAttackObject name.

The complete 25-byte bfmeIsGiantBird helper at 0x001BE9D0 calls AI virtual slot +0x130, zero-extends AL into EAX and returns zero when AI is absent. The source uses its existing integer-returning decoration and explicitly narrows the proven zero-or-one result to a byte, reproducing the target's test AL. The complete ActionManager query at 0x000C58F0 consumes four stack arguments and returns a 32-bit CanAttackResult. Its recorded TheActionManager global resolves to VA 0x012ED700. Raw direct-helper evidence is in build/attack155da0/retail-helpers.log; the strict gate checks these call and global bindings.

The target allocates the 16-byte iterator through the complete global operator new body at 0x00881F30. State 0 covers only its constructor. The FuncInfo at VA 0x011F3494 has one unwind state, no try blocks, and a transition to -1 through cleanup RVA 0x00C04F50. The complete cleanup loads the saved allocation from EBP+8, calls global operator delete at 0x00881EB0 and returns. The handler tail-jumps the MSVCR71 __CxxFrameHandler import route at 0x009F6DD6. The successful main path has no iterator destructor call.

The bank's placement-new glue initially reproduced the main body while emitting a different cleanup that pushed an extra enum argument. The final expression uses global ordinary new. Its emitted cleanup is exactly the retail 11-byte body modulo the independently verified global-delete relocation; its FuncInfo and unwind-state transition agree. Raw evidence is in build/attack155da0/compiled-eh.log, build/attack155da0/runtime-audit.log, build/attack155da0/operator-new.log and build/attack155da0/eh-word-final.log. The cleanup mismatch is resolved, not deferred.

No descriptive regression is reported. The new function and compatibility-pin rows also pass ilt_guard.problems.

The initial check_csv run passed. After conversion, check_csv raises FileNotFoundError for the intentionally deleted bank because its tracked-file inventory still includes that unstaged deletion. Raw output is preserved in build/attack155da0/check-csv.log. The sandbox forbids staging; the coordinator must stage the new source and bank deletion together and rerun check_csv with the commit hooks. The exact conversion remains in the working tree. No shared header, tooling or baseline was edited, so this change does not require a full gate. All trial sources and unedited probe outputs remain under build/attack155da0/.

This recovery would be refuted by a scoped byte or relocation failure on the final source, a caller with a conflicting stack contract, a contained-list constructor copying another payload field, or an emitted unwind action that selects a different deallocator. The retained complete decodes and strict checks address those conditions.
